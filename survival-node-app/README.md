# Survival Node User Guide — Android App Source

This folder holds the source for the **Survival Node User Guide** Android app.

- [`index.html`](index.html) — the complete, self-contained app (inline CSS/JS, no external
  dependencies). This single file **is** the app. Edit it here, then rebuild the Android app.
- [`icon-512-app.png`](icon-512-app.png) — the app launcher icon (512×512, ~124 KB, under
  WebIntoApp's 256 KB limit). ESAI neon logo, same as the support-chat PWA. Upload this in the
  WebIntoApp icon field. Master source: `/icons/support-chat/icon-source.png` (1254×1254).
- `Survival-Node-Users-Guide-v1.2.pdf` — the printable Users Guide PDF (standard letter format).
  Ships pre-loaded on each phone (File Manager → Download) and serves as the offline-shareable / printable
  full copy (e.g. LocalSend to another device in an emergency). **It is generated from
  `/node-setup.html`**, not authored separately — use its "🖨️ Print PDF" button and Save as PDF, or
  headless Chrome against node-setup.html. Regenerate whenever the guide content changes.
  The cover uses `/images/carousel/entirenode/wholekit-gen2.png`, the same Gen 2 kit photo
  used by the product gallery, online guide, and flyer. Regenerate the PDF when this photo changes, too.
  The Power & Solar Charging section uses `/images/carousel/solarbattery/solar-battery-gen2.png`,
  shared with the product gallery and testing page; regenerate the PDF when the battery photo changes.
  (The phone-friendly PDF variant was dropped — the on-phone Users Guide app already covers
  phone-optimized reading.)

## How the app is built

The app is **not** compiled with Android Studio/Gradle. It is generated by
[WebIntoApp.com](https://www.webintoapp.com/), which wraps `index.html` in a WebView Android app
and produces the signed APK/AAB.

**The app must work 100% offline, so `index.html` has to be bundled inside the app.** Build it by
uploading the file in WebIntoApp, never by pointing it at the website URL. A URL build only opens
`https://www.easternshore.ai/survival-node-app/index.html` and fails with no internet, which is
how a Survival Node is used. `index.html` itself needs nothing online (no external fonts, images or
scripts), so keep it that way. Its one network request is the optional update check below.

**Never let the bundled page make a request while the phone is offline.** WebIntoApp's wrapper
handles *any* failed request (not just the page itself: its `onReceivedError` doesn't check
`isForMainFrame`) by loading its online error page, so one failed `fetch` replaces the whole guide
with "Webpage not available". Builds 1.4–1.6 did exactly that in airplane mode, because the update
check fetched `latest.json` on every open. From 1.7 the check only runs when `navigator.onLine` is
true (the app has `ACCESS_NETWORK_STATE`, so the WebView reports airplane mode correctly). Wi-Fi
that is connected but has no internet can still trip it; there is no way to make a request the
wrapper won't treat that way. **Test every build by cold-starting it in airplane mode with Wi-Fi off.**

## To update the app

1. Edit `index.html` in this folder.
2. Keep it in sync with the online guide at `/node-setup.html` and the warranty page at
   `/warranty-insert.html` (the canonical return/warranty policy).
3. Upload `index.html` to WebIntoApp app #1240101 as a bundled file (not the website URL), bump the
   version, and rebuild using the **same keystore**. The versionCode must be higher than the last
   build's (WebIntoApp numbers 1.4 as 10400, so 1.5 is 10500); a lower one won't install over the
   existing app and the Play Store rejects it.
4. Test the new APK on a phone in airplane mode before loading it onto kits.
5. Replace the APK in this folder (named with the version), stamp the footer with the new version,
   and update the table above and the history below.

## Update check (1.4 and later)

[`latest.json`](latest.json) names the newest release and its APK:

```json
{ "version": "1.7", "versionCode": 10700, "apk": "https://www.easternshore.ai/survival-node-app/survival-node-user-guide-v1.7.apk" }
```

`checkForGuideUpdate()` in `index.html` reads it each time the guide opens:

- **Bundled in the app:** if `latest.json`'s `versionCode` is higher than `APP_VERSION_CODE`, the
  orange `#update-note` appears ("Guide update available") with the APK link. Offline, the request
  fails silently (8-second timeout) and nothing shows. The site sends `Access-Control-Allow-Origin: *`,
  which the in-app request needs, and caches files for 10 minutes.
- **Served from easternshore.ai on Android:** that is what app 1.2 loads, and 1.2 can't open
  offline, so the note always shows ("Update to the offline version") with the `latest.json` APK.
  The only known 1.2 install is a phone sold on eBay; drop this branch once it's updated.
- Add `?update-note` to the URL to preview the note anywhere.

### Releasing a new version

1. Edit `index.html`, keep `/node-setup.html` in sync, and regenerate the PDF.
2. Bump `APP_VERSION_CODE` in `index.html` and the footer version (1.5 = 10500, and so on).
3. Zip `index.html` on its own and build it in WebIntoApp's **HTML Files** mode with the same
   Major/Minor version, package and certificate.
4. Check the APK (bundled `index.html` matches, version, signing certificate), add it here as
   `survival-node-user-guide-v<version>.apk`, and list it as the **test** build in `latest.json`
   (leave the top-level fields on the current release):

   ```json
   { "version": "1.7", "versionCode": 10700, "apk": ".../survival-node-user-guide-v1.7.apk",
     "test": { "version": "1.8", "versionCode": 10800, "apk": ".../survival-node-user-guide-v1.8.apk" } }
   ```

5. On the test phone (test updates on, see below), open the guide on Wi-Fi: it shows "Test build
   available". Install it, then **cold-start it in airplane mode with Wi-Fi off** and check the guide
   opens and cards expand.
6. Release: move the test entry's values to the top-level fields, delete `test`, and remove the old
   APK, in one push. Every 1.4+ install sees the update the next time it opens on Wi-Fi.

### Test updates (1.7 and later)

Tap the version line at the bottom of the guide **7 times quickly** to turn test updates on or off
(saved on that phone only; the footer then reads "· test updates on"). With it on, the guide also
offers `latest.json`'s `test` build when it's newer than both the installed version and the
release. Customers' guides ignore `test` (1.4–1.6 don't know it exists). The first install of 1.7
itself has to be done by hand, since 1.6 has no test channel.
